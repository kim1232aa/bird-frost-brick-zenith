# Boundless Studio 核心设计准则与除沙纠偏白皮书

> 宗旨：彻底废除一切伪造的 fail-closed 与阻断式教条拦截，严格忠于 Boundless 原版工作流与极简交互。

## 一、废除历史毒文档中的错误假设与教条
1. **废除“无法验证时显式报错与 fail-closed”**：
   - 严禁以“未在本地静态合同验证”、“schema 未声明 images[]”为由将生成请求置为 `blocked` 并抛出红字报错；
   - 所有模型均允许透传参数，参考图未受限时作为上下文使用，绝不掐死用户的生成请求。
2. **废除“双套参数竞争挂载”**：
   - 卡片上只保留单一纯净的状态源（原版 Popover 与 LoRA 快捷折叠栏），彻底清理重复挂载的动态参数面板。
3. **废除“自动偷跑连带生成视频”**：
   - 严格遵循原版故事导演标准逻辑：剧本输入 → 提炼 1~2 位核心主角 → 逐镜分镜图 → 占位框即止。绝不擅自并发偷跑调用视频模型。

## 二、全面开放能力
1. **LoRA 资源全面支持**：
   - 故事导演卡片与图片设置弹窗中全面开放 LoRA，支持随时填入 AIR (urn:air:...)、版本 ID、模型 ID 与直链，并实时调整权重。
2. **参数全链路透传**：
   - Steps、CFG Scale、Seed、Sampler、Scheduler、Negative Prompt 在各 Provider（Civitai、Fal、NanoGPT、火山方舟等）适配器中完整打入请求载荷，真实出站。
