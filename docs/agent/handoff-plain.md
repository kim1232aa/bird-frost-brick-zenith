# 交接（大白话）

给下一个干活的人看。原文全在 `docs/agent/handoff-user-requirements.md`，这份只按他实际要求说人话。

## 他要的成品

把这个项目修到能当真用。不是看起来能点，是每个板块都能在页面上点出来、生成出来。

一开始就要查：缺憾、bug、空壳、前台和后台对不上、API 参数没接全、功能对不上、没必要的拦截、UI 难看。

有官方文档的，必须对照官方文档，不准瞎编字段。

## 怎么才算过

必须同时满足：

1. 人在页面上点按钮。
2. 真的生成了。
3. 页面显示成功。
4. 生图有图，生视频有视频，图要对得上提示词。
5. 故事导演整条走通。
6. 每个供应商按自己的能力工作，不能一套逻辑打天下。

不算过：测试绿了、curl 通了、脚本直接打 API、换个供应商绕过去。

点到报错就停，查是什么问题，修那个地方。不准掩盖，不准绕过，不准换一家继续刷进度。

每次操作都要截图，各个界面都要截图。他自己觉得你不够苛刻，所以要点击截图一个 agent，看图挑刺另一个 agent。

## 视频工作流（他提过很多次）

核心就一句：**各个 provider 按能力分配。**

- Grok 视频不能只给一张参考图。他说 grok 可不止一张，只给一张就不符合 grok 能力。
- 你支持的时候不要只搞一两个，要按这个供应商实际能力把该给的都给到。
- 修好这个，另一个地方又坏，一堆回归。他怀疑是架构问题，不是零散修。
- 按能力分配视频工作流的图片，提过好多次了。

人物图：

- 错，大错特错，人物图不可以进视频，记下来。
- 人物四象图不可用进视频。
- 他让写死项目 MD。

不要搞多余拦截。功能对不上、参数没接全、拦了不该拦的，都是问题。

## Key 和接线

Key 不应该存在浏览器里面，而是应该在后端处理好。

不准创造他不需要的东西。他没填代理，你就不要搞代理。你直接填了又告诉他没填，这是你弄的回归。

接线问题很多。页面说已填密钥，生成却说中转没有密钥，这种必须当 bug 修，不能当用户没配。

他问过：哪些是他明确要求改的，哪些是你做的回归。别把你自己加的东西说成他要的。

## 怎么干活

代码：

- 后面别开写代码的 agent 了。
- 代码你直接写，或者复用已用过的 agent。
- 新 agent 老要重新读取文件。
- 先别开子代理，复用老代理，或者你自己做。
- agent 中断了要恢复，不要另开。
- 审查代码用 deepseek / luna；改代码只能用 gpt-sol。deepseek 不能用来改代码，按能力分配。
- 点击、挑刺、死代码盘点可以用 grok 子 agent。
- 按能力分配 agent，看看模型池。能并行的别干等。开就不要只开一两个。

不准：

- 未经授权删减、精简功能。
- 私自安装工具。他没允许装 Chromium / Playwright / 别的 CLI。
- 堆很多测试容器。只留一个最新的。清这个项目的垃圾、构建垃圾、缓存。
- 工作区太脏。测完清。
- 未经他说就 commit / push。他说了才做。说过两次：`commit pust 到main`、`commit pust 做个交接文档吧`。
- 把本地通过说成公网通过。预览站之前挂过，没部署新代码就不算公网好了。

项目约束、其他约束可能都是错的，都需要大修。别把错误的 MD 当圣旨，但用户没要过的入口不要挂顶栏。
